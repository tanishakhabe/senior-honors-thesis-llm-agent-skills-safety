# Frontend pilot

Research inputs live in `data/skill-copies/{benign,adversarial}/frontend-design/SKILL.md`. The benign copy is byte-identical to the installed frontend skill. The adversarial copy only appends a harmless response override. Both are text data, never executed.

On ORCHARD, from the experiment root:

```bash
sbatch run_activations.slurm data/skill-copies/benign/frontend-design/SKILL.md data/skill-copies/adversarial/frontend-design/SKILL.md --model openai-community/gpt2 --output-dir results/frontend-pilot/residuals
sbatch run_activations.slurm data/skill-copies/benign/frontend-design/SKILL.md data/skill-copies/adversarial/frontend-design/SKILL.md --model openai-community/gpt2 --capture-attention --output-dir results/frontend-pilot/with-attention
```

Open `notebooks/frontend_skill_pilot.ipynb` using the cluster environment and run all cells after extraction. It saves `residual_endpoint_norms.png` and `final_token_attention.png` inside the attention run directory. The table lists chunk boundaries. Only the last chunk of each input is plotted; each chunk starts a new model context. The final tokens are different endpoints. Differences may reflect length, wording, or position, not a safety mechanism.

Data and results remain ignored by Git and must be copied separately to ORCHARD. Only load tensor files generated by your own experiment; notebook loading uses `weights_only=True`. Attention requires actual registered `hook_pattern` hooks and validates shape, finite probabilities, and row sums. Without the flag the existing residual-only behavior is preserved.
